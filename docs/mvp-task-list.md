# mirascope MVP 详细任务清单

## 1. 文档目标

这份清单用于把 `plan.md` 中的总计划，继续下沉成可执行的 MVP 任务列表。

使用原则：

- 只关注 MVP 必须完成的内容
- 每个阶段只解决一个核心问题
- 优先完成可闭环能力，不追求表面功能数量

---

## 2. MVP 定义

MVP 的目标不是一次性做完整个平台，而是验证以下三件事：

1. 用户是否愿意长期用它管理小说和漫画
2. 本地阅读体验是否足够稳定顺手
3. 数据模型是否能平滑扩展到同步和番剧模块

### MVP 范围

必须包含：

- 基础 App 架构
- 小说阅读
- 漫画阅读
- 本地书架/媒体库
- 收藏与历史记录
- 账号与基础同步

暂不纳入 MVP：

- AI 功能
- 社区功能
- 推荐系统
- VIP 与商业化
- 复杂视频能力

---

## 3. 阶段拆解

- [ ] 明确目录结构

## 4. 优先级标记

### P0 - 不做就不算 MVP

- 项目骨架
- 本地数据模型
- 小说阅读
- 漫画阅读
- 账号登录
- 收藏/历史同步

### P1 - 强烈建议在 MVP 结束前完成

- 设置同步
- 图片缓存优化
- 阅读器交互优化
- 日志与错误处理

### P2 - 可以延后到 Beta

- 番剧模块
- 下载系统
- 搜索增强
- 推荐系统

---

## 5. 建议开发顺序

建议严格按下面顺序推进：

1. 工程骨架
2. 本地数据模型
3. 小说阅读
4. 漫画阅读
5. 账号与同步
6. MVP 打磨

原因：

- 阅读体验是产品价值核心
- 数据模型越早定下来，后面越省事
- 同步必须建立在本地正确之上

---

## 6. 验收清单

MVP 完成前，至少逐项确认：

- [ ] App 已脱离默认模板
- [ ] 小说导入与阅读闭环可用
- [ ] 漫画搜索与阅读闭环可用
- [ ] 收藏和历史本地可持久化
- [ ] 登录流程可用
- [ ] 多设备同步可用
- [ ] 常见异常不会导致数据丢失
- [ ] 至少一个移动端和一个桌面端可稳定运行

---

## 7. 一句话执行原则

先把“小说 + 漫画 + 本地数据 + 基础同步”做成一个稳定产品，再考虑视频、下载、推荐和商业化。
