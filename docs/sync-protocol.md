# mirascope 同步协议

## 1. 状态与范围

本文定义 Version 0.6 的目标协议，不代表当前已经实现同步。进入 Version 0.6 前必须结合实际本地 schema、Version 0.4 备份恢复语义和 API 原型复核。

首期同步收藏、阅读进度、书签和阅读设置；不上传小说正文、漫画图片或用户原始文件。

## 2. 协议原则

- 本地写入先成功，网络同步是增强能力；
- 每项操作可重试且幂等；
- 服务端顺序不依赖客户端时钟；
- 删除必须传播，不能靠“查不到”推断；
- 协议需要版本和兼容策略；
- 同步失败不得破坏本地阅读。

## 3. 标识和版本

- `entityId`：客户端生成的稳定 UUID；
- `operationId`：每次本地变更生成的稳定 UUID，重试不改变；
- `deviceId`：服务端登记且可撤销的设备标识；
- `entityVersion`：服务端对单实体成功变更后递增；
- `syncCursor`：服务端变更流中的不透明单调游标；
- `protocolVersion`：请求明确携带的协议版本。

客户端 `updatedAt` 只用于展示和诊断，不能作为唯一冲突依据。

## 4. 客户端操作日志

本地业务事务同时更新领域实体并写入待同步操作。操作至少包含：

```text
operationId
deviceId
entityType
entityId
baseEntityVersion
operationType
payload
createdAt
retryCount
```

`operationType` 为 `upsert` 或 `delete`。同一 `operationId` 在服务端只能产生一次效果。

## 5. 同步流程

### 5.1 首次同步

1. 登录并登记设备；
2. 拉取服务端快照及当前游标；
3. 在本地事务中合并快照；
4. 上传本地尚未确认的操作；
5. 拉取上传期间产生的新变化；
6. 保存最终游标。

### 5.2 增量同步

1. 按创建顺序上传待处理操作；
2. 服务端返回应用结果、实体版本和冲突；
3. 客户端事务性确认成功操作；
4. 使用 `syncCursor` 拉取远端变化；
5. 合并后原子保存新游标。

响应丢失时客户端使用相同 `operationId` 重试。

## 6. 冲突规则

- 收藏：使用明确的收藏/取消收藏操作和服务端实体版本，不比较设备时间；
- 进度：默认保留双方候选，自动选择更靠后的有效语义位置用于展示，并允许恢复另一位置；
- 书签：不同 ID 合并；同一 ID 的编辑按 `baseEntityVersion` 检测冲突；
- 阅读设置：字段级合并；同一字段冲突由服务端接收顺序决定，并返回被覆盖值供诊断；
- 无法自动处理的冲突：保留本地快照和远端快照，显示可解释的恢复选择。

客户端提交的 `baseEntityVersion` 落后且操作不可安全合并时，服务端必须返回冲突，不静默覆盖。

## 7. 删除

删除使用 tombstone，至少包含实体 ID、删除版本和服务端删除时间。客户端确认所有活跃设备已越过对应游标或达到明确保留期后，服务端才可清理 tombstone。

离线设备重新上线时必须先消费删除事件。恢复已删除实体使用新的显式操作，不能删除本地 tombstone 后假装从未删除。

## 8. 游标失效与恢复

服务端无法继续某个旧游标时返回明确的 `cursor_expired`。客户端随后：

1. 保留未确认的本地操作；
2. 下载新快照；
3. 在事务中重建可同步镜像；
4. 重新应用未确认操作；
5. 从新游标继续。

本地数据库损坏或用户主动重置时采用相同的快照恢复流程。

## 9. 重试和节流

- 网络和服务端临时错误使用指数退避与随机抖动；
- 鉴权错误先刷新 Token，失败后停止后台重试并要求登录；
- 校验错误和协议不兼容不自动无限重试；
- 前台关键操作可触发节流同步，频繁进度变化应合并；
- 连续失败必须可在诊断页面看到错误类别和最近时间。

## 10. 安全与隐私

- 全部请求使用 HTTPS；
- Token 使用平台安全存储，不写入普通日志；
- 日志脱敏，不包含正文、图片和完整文件路径；
- 设备可查看和撤销；
- 用户能够请求导出和删除云端账号数据；
- 服务端实施最小权限、请求大小限制、速率限制和审计记录。

## 11. API 最小语义

具体路径可调整，但需要等价能力：

```text
POST /auth/register
POST /auth/login
POST /auth/refresh
GET  /devices
DELETE /devices/{id}
POST /sync/push
GET  /sync/pull?cursor=...
GET  /sync/snapshot
```

错误响应至少包含稳定错误代码、请求 ID 和可安全展示的消息。协议变更必须兼容上一发布客户端，或明确阻止不兼容客户端继续写入。

## 12. 验收

- 相同 `operationId` 重放不会重复修改；
- 两台设备离线修改后能够合并或得到明确冲突；
- 删除能传播到长期离线后重新上线的设备；
- 客户端时间错误不改变服务端顺序；
- 响应丢失后重试不会重复应用；
- 游标失效后能够保留未上传操作并重建；
- 同步失败时本地阅读、收藏和进度仍可使用；
- Token、正文和敏感路径不进入日志。
