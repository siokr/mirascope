# mirascope 小说导入与阅读器规格

## 1. 范围

- MVP 0.1：TXT、Windows、本地阅读闭环。
- MVP 0.2：EPUB、Android、书签和体验打磨。

本文定义产品行为；实体语义以 `docs/data-model.md` 为准。

## 2. MVP 0.1 核心流程

```text
选择 TXT -> 检查文件与重复项 -> 识别编码 -> 提取标题和章节
-> 原子写入媒体库 -> 阅读 -> 保存位置 -> 重新启动并恢复
```

任何一步失败都必须给出明确结果，不能把乱码、空正文或不完整记录当作成功。

## 3. TXT 导入

### 3.1 输入

- 文件必须可读且非空；
- `.txt` 扩展名不区分大小写，但扩展名不是可信内容依据；
- 路径失效、权限和 I/O 错误使用不同错误代码；
- 导入前按数据模型计算或确认指纹。

### 3.2 编码

MVP 0.1 支持 UTF-8、带可识别 BOM 的 UTF-16 LE/BE，以及 GB18030。

识别顺序：

1. 检查 BOM；
2. 验证 UTF-8；
3. 以确定性策略评估 GB18030；
4. 无法可靠判断时让用户选择并预览。

不得自动使用系统默认编码。用户确认的编码写入导入元数据，重新解析时复用。

### 3.3 规范化

- 内部换行统一为 `\n`；
- 保留段落边界并移除 BOM；
- 不静默转换繁简、全角字符或标点；
- 连续空行的显示优化不破坏原始定位；
- 不修改原文件。

默认标题取文件名。作者信息不从正文猜测。MVP 0.1 使用稳定默认封面即可。

## 4. 章节识别

规则至少覆盖独占一行的常见格式：

```text
第1章 标题
第一章 标题
第 12 章 标题
第十二回 标题
卷一 标题
第一卷 标题
Chapter 1 Title
```

要求：

- 标题行有合理长度上限；
- 正文中偶然出现章节字样不切章；
- 保留识别依据和原始字符偏移；
- 不产生大量空章节；
- 具体正则和阈值由样例测试确定。

无法可靠识别时创建单一“正文”章节，用户仍能完整阅读。重新解析必须先生成新结果，再映射旧章节和进度，整个替换过程原子化。

## 5. 导入事务

1. 创建状态为 `pending` 的 `ImportRecord`；
2. 在临时区域解码、规范化并建立章节索引；
3. 验证存在可读正文；
4. 在事务中写入媒体、媒体库和章节；
5. 原子移动派生文件；
6. 标记为 `completed`。

失败时回滚数据库、清理未引用临时文件，将记录标记为 `failed` 并保存稳定错误代码。用户原文件不被修改。

## 6. 重复与文件变化

- 指纹相同：提示已导入并打开已有作品；
- 标题相同、指纹不同：允许作为不同作品；
- 路径相同、内容变化：提示重新解析；
- 文件移动或丢失：保留状态并允许重新定位；
- 重新定位的指纹不同：要求用户确认更新或取消。

## 7. 阅读器

### 7.1 MVP 0.1 功能

- 正文、当前章节和总进度；
- 上一章、下一章和目录入口；
- 阅读设置和返回入口；
- 鼠标、键盘和窗口尺寸变化的桌面交互；
- 稳定的纵向滚动模式。

分页模式不是 MVP 0.1 完成条件。

### 7.2 设置

支持字号、行距、浅色、深色和至少一个护眼主题。变更即时预览并写入 `ReaderPreference`，无效设置安全回退。

### 7.3 导航

目录按 `orderIndex` 展示并标记当前章节。首尾章节不提供无效跳转；切章失败时保留当前可读内容并显示错误。

## 8. 进度保存与恢复

进度至少包含 `contentUnitId`、章节内字符偏移或等价稳定定位、展示进度和 `revision`。不能只保存滚动像素。

保存时机：

- 切章后立即保存；
- 位置变化后节流保存；
- 进入后台或窗口关闭前尝试刷新；
- 重新排版后保存语义位置；
- 异常终止恢复不只依赖正常退出回调。

节流期间新位置覆盖旧待写位置，旧异步写入不得覆盖更高 `revision`。

恢复依次尝试原章节、稳定定位、重新解析映射和章节开头回退。文件丢失时保留进度并提供重新定位。

## 9. 错误模型

| 错误代码 | 含义 | 用户行为 |
|---|---|---|
| `file_not_found` | 路径失效 | 重新选择 |
| `file_permission_denied` | 无读取权限 | 调整权限或复制文件 |
| `empty_file` | 无正文 | 取消导入 |
| `encoding_unknown` | 编码不可靠 | 手动选择并预览 |
| `decode_failed` | 解码失败 | 更换编码或取消 |
| `no_readable_content` | 无可读内容 | 检查文件 |
| `import_duplicate` | 指纹已存在 | 打开已有作品 |
| `parse_failed` | 解析失败 | 保留失败记录并重试 |
| `storage_failed` | 数据或文件写入失败 | 回滚并重试 |
| `source_changed` | 原文件已变化 | 确认重新解析 |

日志可记录错误代码、阶段、文件大小和耗时，不记录正文或完整敏感路径。

## 10. MVP 0.2 EPUB 边界

支持未加密的常规 EPUB 2/3 文本内容、OPF、NCX 或 Navigation Document、章节 XHTML、本地图片和基础样式。

首版不支持 DRM、依赖脚本的交互内容、固定版式像素级还原、音视频和复杂 MathML 的完整呈现，以及远程资源自动下载。

容器损坏、清单缺失、资源缺失和危险路径必须拒绝或降级；解压需要防止路径穿越和超大展开。

## 11. 验收场景

- UTF-8、UTF-16 和 GB18030 样例按规则导入；
- 无法可靠识别的文件进入编码选择，不直接乱码；
- 无章节文件以单一“正文”章节可读；
- 常见章节样例产生稳定目录；
- 重复文件不生成重复活动条目；
- 设置和语义位置在重启后恢复；
- 文件移动后可重新定位并保留进度；
- 导入失败不留下半完成条目和孤立派生文件；
- 重新解析失败保留旧的可读版本；
- 旧进度写入不覆盖新进度。

## 12. 性能记录

使用小型、常规和 50 MB TXT 样例记录编码、文件大小、章节数、机器、系统、Flutter/Dart 版本、构建模式、导入耗时、打开耗时、峰值内存，以及至少三次运行的中位数。

建立基线前不填写缺乏依据的硬阈值，冻结和回归规则由 `docs/quality-strategy.md` 定义。

## 13. 测试重点

- 编码与解码单元测试；
- 章节样例表驱动测试；
- 指纹和重复导入测试；
- 导入回滚集成测试；
- `revision` 并发写入测试；
- 排版变化后的定位恢复测试；
- 媒体库到阅读器的 Widget 流程；
- Windows 核心演示路径手工验证。
