# mirascope 发布检查清单

## 1. 使用方式

每个候选版本复制本清单到 Release 说明或发布记录中逐项确认。勾选表示已经获得证据，不表示计划稍后完成。

## 2. 范围与状态

- [ ] 版本范围与 `plan.md` 一致
- [ ] README 的“已实现/开发中/计划”与代码一致
- [ ] 非目标能力没有出现在支持列表
- [ ] 已知问题和限制已记录

## 3. 代码与数据

- [ ] 版本号和构建号已更新
- [ ] 依赖锁文件与发布提交一致
- [ ] 数据库从上一发布版本迁移成功
- [x] 迁移失败和数据恢复路径已验证
  - v1 合成迁移与整目录备份恢复流程：
    [`v1-migration-and-backup-acceptance.md`](v1-migration-and-backup-acceptance.md)
- [ ] 不包含 Token、密码、私有路径或测试账号

## 4. 自动检查

- [ ] `dart format --output=none --set-exit-if-changed lib test tool bin`
- [ ] `flutter analyze`
- [ ] `flutter test`
- [ ] 当前支持平台的 release 构建
- [ ] 命令、日期、提交和结果已记录

## 5. 手工验证

- [ ] 当前版本核心演示路径完整通过
- [ ] 正常关闭后恢复阅读位置
- [ ] 异常终止后恢复阅读位置
- [ ] 空数据、加载、错误和重试状态可理解
- [ ] 键盘、鼠标及目标设备主要交互可用

## 6. 性能

- [ ] 使用固定样本完成基准
- [ ] 记录机器、构建模式、运行次数和中位数
- [ ] 与上一版本比较并解释明显回归
- [ ] 内存或磁盘占用没有未解释增长

## 7. GitHub 发布物

- [ ] README 包含可复现安装或运行步骤
- [ ] 截图或短演示来自该发布版本
- [ ] Release Notes 说明新增、修复、迁移和已知问题
- [ ] 安装包名称包含平台、版本和架构
- [ ] 文件哈希已生成
- [ ] LICENSE 和第三方许可证信息准确

## 8. 回滚与支持

- [ ] 明确数据是否支持回到旧版本
- [ ] 不支持降级时已经警告用户
- [ ] 日志导出方式可用于问题定位
- [ ] 阻塞和严重缺陷处置方式已明确

## 9. 发布后

- [ ] 在干净环境安装最终产物
- [ ] 再次执行核心路径
- [x] Git 标签与提交一致
- [ ] GitHub Release 页面链接和附件可访问
- [ ] 记录首轮真实使用反馈
