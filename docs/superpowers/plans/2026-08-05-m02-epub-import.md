# MVP 0.2 EPUB 实施计划

## 原则

先完成 Windows EPUB 闭环，再开始 Android、书签和阅读体验完善。任务 1—4 完成前不接 UI；任务 5—6 完成前不写入成功媒体记录；所有压缩包访问只经过安全容器层。

## 任务

1. **依赖与样本尖峰**：审计 `archive`、`xml`、`html` 的许可证和平台兼容性，建立可再分发 EPUB 2/3 最小样本并锁定版本。
2. **文件准备**：接入 EPUB 选择、扩展名/签名/大小检查、流式指纹、重复项识别和稳定错误映射。
3. **安全 ZIP 容器**：实现路径规范化、二次验证、entry/大小/压缩比预算和受控资源读取，补齐攻击样本测试。
4. **EPUB 结构解析**：解析 container、OPF、manifest、spine、NCX/nav、fragment 与基础元数据，明确缺失资源和 DRM 行为。
5. **XHTML 规范化**：转换语义块，清理活动内容与外部引用，提取本地图片，定义不支持元素的安全降级。
6. **派生存储与事务**：暂存并提升 manifest、章节 JSON 和图片，复用原子数据库提交与失败清理；仅在确有字段需求时引入 schema v3。
7. **详情、阅读与进度**：展示 EPUB 目录和内容，支持章节跳转、键盘操作、语义进度保存恢复及来源丢失后的派生内容阅读。
8. **Windows UI 与验收**：补充导入入口、中文错误、加载/取消状态、自动化回归和 Windows Sandbox 人工流程。

## 后续任务

Windows EPUB 稳定后依次评估：Android 主流程、书签、布局/导航/无障碍完善、性能与 `v0.2.0` 发布。漫画、在线内容源、账号和同步不属于本阶段。

## 质量门槛

每项完成都要记录当次测试证据，不沿用 MVP 0.1 数字。至少执行格式化、静态分析、单元/组件/集成测试、TXT 回归、恶意 EPUB 测试、失败回滚测试和干净环境人工验收。
