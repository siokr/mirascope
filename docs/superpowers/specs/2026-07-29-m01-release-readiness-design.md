# M01-018 MVP 0.1 候选发布收口设计

## 目标

把当前工程从“代码已实现但仓库门面过期”推进到可供求职展示、个人试用和 GitHub 交流的候选状态。所有状态必须能指向代码、自动检查、构建、基准或人工验收证据。

## 发布状态

MVP 0.1 使用 `0.1.0+1` 作为首个候选版本。它不是正式稳定发布承诺：

- 自动化领域、数据层和 Widget 测试已经覆盖主要规则；
- GitHub Windows runner 可以生成 release 构建；
- 本机 MSVC 工具链仍阻止真实 Windows 启动；
- 核心演示路径、正常/异常退出恢复和原生文件选择尚未人工验收；
- 不同指纹来源确认后的安全原位重解析尚未实现。

在上述人工验收完成前，状态只能是“候选/预发布”，不能写成“正式可用版本”。

## 仓库入口

根 README 面向第一次访问者，首屏需要回答：

1. 这是做什么的；
2. 当前真实完成到哪里；
3. 有哪些可验证的工程亮点；
4. 如何运行和检查；
5. 哪些能力还没有；
6. 从哪里阅读设计与证据。

删除“仍是 Flutter 初始模板”等过期表述，不把 Windows 构建通过等同于实机使用通过。

## 发布材料

- `README.md`：真实项目状态、能力、架构、质量证据、运行入口；
- `docs/demo-guide.md`：可重复的 5–8 分钟核心演示脚本；
- `docs/known-issues.md`：限制、影响、绕行与后续处理；
- `docs/releases/0.1.0-rc.1.md`：候选版本说明和发布清单证据；
- `docs/dev-setup.md`：小白可执行的运行、检查和常见问题；
- `pubspec.yaml`：版本与项目描述；
- README 截图区域：只有取得当前候选构建的真实图像后才加入，不使用设计稿冒充运行截图。

## 导入入口阻塞

审计发现底层文件选择、指纹、解码、章节识别、原子导入和生产 Provider 均已存在，但 `LibraryPage` 没有调用这些能力，现有空媒体库页面也没有导入按钮。候选版本必须补齐：

1. 媒体库提供明确的“导入 TXT”入口；
2. 选择新文件后允许填写或确认书名；
3. 自动编码无法确定时允许选择 UTF-8、UTF-16 LE/BE 或 GB18030 后重试；
4. 重复文件直接打开已有作品；
5. 成功导入刷新媒体库并打开详情；
6. 取消不是错误，失败只展示安全错误信息；
7. 导入期间禁用重复操作。

不得为了收口绕过现有应用用例，让页面直接读取文件或写数据库。

## 演示路径

演示只覆盖 MVP 0.1：

```text
空媒体库
→ 导入自建 TXT
→ 查看详情与目录
→ 打开阅读器
→ 调整字号/行距/主题
→ 切换章节并产生进度
→ 关闭并重启
→ 恢复阅读位置
→ 移动原文件
→ 使用同一内容重新定位
```

重复导入、错误编码、归档/恢复和不同指纹保护作为补充路径。

## 安全与发布边界

- 不提交真实私人小说、路径或日志；
- 不把 GitHub Actions 构建物描述为已安装验证；
- 不生成假的运行截图；
- 不创建 Git 标签或 GitHub Release，除非用户明确授权；
- 不擅自选择开源许可证；缺少许可证必须列为公开分发前待决策项；
- 不声称支持 EPUB、Android、漫画、同步、在线源或下载。

## 完成定义

M01-018 只有同时满足以下条件才可标记 `done`：

- README、运行指南、演示指南、已知问题和候选说明一致；
- 版本号、锁文件、自动检查、Windows release 构建有当次证据；
- 在真实 Windows 应用中执行核心演示路径；
- 取得候选版本真实截图或短演示；
- 从干净环境复现运行或安装；
- 发布清单逐项标记通过、不适用或阻塞；
- 许可证决策完成。

若本机工具链继续阻塞，文档与自动化部分可以完成，但 M01-018 保持 `blocked`。
