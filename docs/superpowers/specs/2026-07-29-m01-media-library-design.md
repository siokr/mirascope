# M01-006 媒体库设计

## 1. 目标

为 mirascope MVP 0.1 提供正式的本地媒体库界面，让用户能够：

- 查看当前书架；
- 按最近打开时间找到内容；
- 打开小说详情；
- 将内容移入归档；
- 查看归档内容并恢复；
- 在重启应用后看到一致状态。

本阶段建立可展示、可测试的媒体库体验，但不提前实现 TXT 文件选择、文件解析或导入流程。

## 2. 范围

### 2.1 本阶段包含

- 活动媒体库响应式查询；
- 归档媒体库响应式查询；
- 最近打开排序；
- 打开作品时持久化 `lastOpenedAt`；
- 归档与恢复；
- 加载、空、错误、正常四类界面状态；
- 自适应封面网格；
- 无封面时的稳定占位视觉；
- Riverpod 状态接入；
- 媒体库 Repository、状态层和 Widget 测试；
- 键盘、Tooltip、语义标签和窄窗口适配。

### 2.2 本阶段不包含

- 文件选择器；
- TXT 指纹、编码识别、解析与导入；
- 搜索、筛选和批量操作；
- 收藏切换；
- 永久删除应用数据；
- 真实封面提取、联网封面或图片缓存；
- 小说详情和阅读器正式实现；
- 漫画导入。

空状态可以说明后续通过 TXT 导入建立书架，但不提供无效或伪造的导入按钮。

## 3. 设计判断

这是面向日常阅读用户、同时会被招聘者审视的 Flutter 桌面产品界面，采用克制、清晰、略带编辑感的 Material 3 语言。

- 设计变化：4。保持产品界面稳定，在封面比例、留白和排版上建立识别度。
- 动效强度：3。只使用 Material 状态过渡和必要的交互反馈。
- 信息密度：5。桌面端充分利用宽度，但不把媒体库做成管理后台。

现有应用已经采用 Material 3，因此继续使用同一设计系统，不引入第二套组件体系或额外 UI 依赖。

## 4. 信息架构与导航

### 4.1 活动媒体库

保留 `/library` 作为应用首页。

页面顶部包含：

- 标题“媒体库”；
- “已归档”入口；
- “设置”入口。

内容区域根据异步状态显示加载骨架、空状态、错误状态或封面网格。

### 4.2 已归档页面

新增 `/library/archive`。

该页面使用标准返回导航，标题为“已归档”，只显示已经归档的条目。每个条目提供恢复操作，不提供永久删除。

归档列表按 `archivedAt` 降序排列；时间相同时按 `addedAt` 降序排列。恢复后条目立即从归档页消失，并重新出现在活动媒体库中。

### 4.3 打开作品

点击活动媒体卡片时按以下顺序执行：

1. 使用注入的 UTC 时钟生成打开时间；
2. 持久化对应条目的 `lastOpenedAt`；
3. 按媒体类型导航。

MVP 0.1 只有小说可进入详情页。遇到当前版本不支持的媒体类型时，保留在当前页并显示稳定、可理解的提示，不写原始异常。

打开时间写入失败时不导航，显示可重试的错误提示，避免界面顺序与持久化顺序不一致。

## 5. 数据与领域接口

`MediaLibraryRepository` 增加：

```dart
Stream<List<LibraryItem>> watchArchivedLibrary();
Future<void> markOpened(String mediaItemId, DateTime openedAt);
```

原有接口保持：

```dart
Stream<List<LibraryItem>> watchActiveLibrary();
Future<MediaItem?> findMediaItem(String mediaItemId);
Future<void> archive(String mediaItemId, DateTime archivedAt);
Future<void> restore(String mediaItemId);
Future<void> deleteApplicationData(String mediaItemId);
```

约束：

- `markOpened` 只更新存在且未归档的媒体库条目；
- `archive` 只更新存在且未归档的条目；
- `restore` 只更新存在且已归档的条目；
- 更新目标不存在或状态不匹配时抛出领域可识别的错误，状态层将其映射为稳定用户提示；
- 所有时间进入 Repository 前统一为 UTC；
- 归档和恢复不删除 `MediaItem`，不访问或删除用户原文件。

本阶段不在界面暴露 `deleteApplicationData`。

## 6. 状态管理

在 library feature 内增加 Riverpod 状态：

- `activeLibraryProvider`：监听活动媒体库；
- `archivedLibraryProvider`：监听归档媒体库；
- `libraryActionsProvider`：执行打开、归档与恢复；
- `libraryClockProvider`：提供可替换 UTC 时钟，保证测试确定性。

页面直接消费 `AsyncValue<List<LibraryItem>>`：

- loading：显示与最终网格尺寸一致的骨架；
- data empty：显示对应空状态；
- data non-empty：显示封面网格；
- error：显示稳定错误说明和“重试”操作。

动作状态与列表流分开，避免归档一项时把整个书架替换成全屏加载。

同一条目的动作进行中时禁用重复操作。失败后保留原列表，由流中的数据库事实决定最终状态。

## 7. 界面规范

### 7.1 封面网格

使用 `LayoutBuilder` 和最大内容宽度建立自适应网格：

- 窄窗口：2 列；
- 中等窗口：3 至 4 列；
- 宽窗口：最多 6 列；
- 卡片宽度保持可读，不随超宽窗口无限拉伸。

卡片包含：

- 约 2:3 的封面区域；
- 标题，最多两行；
- 作者或副标题，最多一行；
- 最近打开信息，未打开时显示“尚未阅读”；
- 更多操作菜单。

无真实封面时使用由标题首字和媒体类型构成的 Material 占位封面。颜色从固定、低饱和调色板按媒体 ID 稳定选择，不能每次启动变化。

不使用装饰性渐变、发光、玻璃拟态或过度阴影。卡片圆角与应用其他组件保持统一。

### 7.2 交互

- 点击卡片主体：打开作品；
- 更多菜单：归档或恢复；
- 归档前显示确认对话框，明确说明“不会删除原文件”；
- 归档成功后允许通过 SnackBar 撤销；
- 恢复成功后使用简短 SnackBar 确认；
- 菜单、按钮和卡片都有 Tooltip、焦点状态和语义标签；
- 不把右键作为唯一操作入口。

### 7.3 空状态

活动媒体库为空：

- 标题：“媒体库还是空的”；
- 说明：“导入 TXT 小说后，它会出现在这里。”；
- M01-007 完成前不显示导入按钮。

归档为空：

- 标题：“没有已归档内容”；
- 说明：“归档的作品会保留在这里，也不会删除原文件。”。

### 7.4 错误状态

列表读取失败时显示：

- 标题：“暂时无法读取媒体库”；
- 稳定提示，不包含数据库异常、堆栈或路径；
- “重试”按钮。

动作失败使用 SnackBar：

- 打开失败：“无法打开这本书，请重试。”；
- 归档失败：“无法归档，请重试。”；
- 恢复失败：“无法恢复，请重试。”。

错误详情只进入安全日志代码，不记录标题、文件路径或原始数据库异常。

## 8. 排序与一致性

活动媒体库排序：

1. 已打开条目优先；
2. `lastOpenedAt` 降序；
3. 未打开条目按 `addedAt` 降序；
4. 最后以 `LibraryEntry.id` 升序作为稳定并列顺序。

归档媒体库排序：

1. `archivedAt` 降序；
2. `addedAt` 降序；
3. `LibraryEntry.id` 升序。

Repository 查询明确包含全部排序项，避免 SQLite 在时间相同时返回不稳定顺序。

界面不自行重排数据库结果。应用重启后只依赖持久化字段恢复顺序。

## 9. 测试策略

### 9.1 Repository 测试

- 活动流排除归档条目；
- 归档流只包含归档条目；
- 两类流均具有稳定排序；
- `markOpened` 更新 UTC 时间并改变活动列表顺序；
- 已归档条目不能被 `markOpened`；
- 归档、恢复针对错误状态时失败；
- 归档与恢复复用同一条 `LibraryEntry`；
- 归档和恢复不删除 `MediaItem`、导入记录或源文件引用。

### 9.2 状态层测试

- Provider 使用注入 Repository 和时钟；
- 打开成功先写时间再导航；
- 打开时间写入失败时不导航；
- 动作重复提交被阻止；
- Repository 异常映射为稳定界面状态。

### 9.3 Widget 测试

- 加载骨架；
- 活动空状态；
- 归档空状态；
- 错误与重试；
- 多条媒体的封面网格及关键信息；
- 卡片打开小说详情；
- 归档确认文案明确不删除原文件；
- 归档成功、撤销和失败；
- 归档页恢复成功和失败；
- 窄窗口无溢出；
- Tooltip、语义标签和键盘焦点存在。

### 9.4 集成证据

使用同一个临时本地数据库实例验证：

1. 插入媒体和书架条目；
2. 页面出现条目；
3. 打开后 `lastOpenedAt` 持久化；
4. 重新创建 Provider 容器后顺序保持；
5. 归档后活动页消失、归档页出现；
6. 恢复后重新出现在活动页；
7. 用户原文件路径和记录仍存在。

## 10. 完成标准

只有同时满足以下条件，M01-006 才能标记为 `done`：

- 活动与归档媒体库都由真实 Repository 流驱动；
- 加载、空、错误、正常状态均有测试；
- 最近打开排序在重启后保持；
- 归档、撤销和恢复行为通过测试；
- 归档不会删除用户原文件或应用数据；
- 窄窗口无布局溢出；
- 普通日志不包含标题、路径、原始异常或堆栈；
- 全量 `flutter test --no-pub` 通过；
- `flutter analyze --no-pub` 通过；
- 独立代码复审无阻塞问题。
