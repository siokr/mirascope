# Version 0.3 本地漫画实施设计

## 1. 目标

在不引入在线内容源的前提下，让现有统一媒体库承载第二种媒介，完成本地漫画从导入、章节组织、阅读到进度恢复和缓存清理的双平台闭环。

## 2. 已冻结范围

- 输入：用户主动选择的本地目录、ZIP 或 CBZ；
- 图片：JPEG、PNG、WebP，最终支持以 Windows 与 Android 的真实解码测试为准；
- 阅读：纵向连续滚动、横向单页、左右两种翻页方向；
- 状态：章节、固化页序、页级进度、漫画阅读偏好、来源状态；
- 派生内容：封面/缩略图、页清单和有边界的可删除缓存。

双页、RAR/CBR、7z、PDF、在线源、站点规则、云端下载和番剧不属于 0.3。

## 3. 关键决策

### 3.1 先扫描，后提交

来源先进入只读扫描和验证阶段，产生稳定章节/页清单；缩略图写入临时区；只有全部结构门槛通过后，才在单个数据库事务中提交媒体、书架、章节和导入记录，再原子采用派生目录。

### 3.2 页序是导入结果

自然排序只在扫描时计算。页序和章节序随后写入持久化清单，阅读器不得每次打开时重新遍历来源。这样可以避免平台枚举顺序变化，也为将来的显式调序保留稳定语义。

### 3.3 原始来源与缓存分离

目录、ZIP/CBZ 和图片始终属于用户；应用只读。缩略图、解码缓存和预加载结果属于可删除派生数据。清缓存、归档和永久删除都不得删除原始来源。

### 3.4 目录权限先验证

Windows 路径和 Android 文档树不是同一种持久访问模型。`M03-003` 必须用真实平台验证目录选择、重启后访问和权限失效行为。若现有选择器不能安全保留 Android 目录访问权，先完成 ZIP/CBZ 闭环，并把目录支持保持为显式阻塞，不通过复制整个原目录绕过权限问题。

### 3.5 缓存数值由基准决定

预加载窗口、内存上限和磁盘上限不在设计阶段拍脑袋固定。先实现可测量策略，再用小章节、大章节、大图和快速翻页记录峰值、命中和取消行为，最后冻结默认值。

## 4. 安全边界

- 规范化压缩包路径后拒绝绝对路径、盘符、`..` 越界、重复文件/目录冲突；
- 在解压或解码前检查条目数、声明大小、实际读取量和总预算；
- 加密包、损坏中央目录和不支持格式整体拒绝；
- 单张损坏图片可形成可见占位，但整章没有可读页时不写入活动章节；
- 日志只记录稳定错误码和阶段，不记录完整路径、图片数据或原始异常；
- 来源变化后缓存键必须失效，不能继续显示旧图片。

## 5. 数据与界面边界

漫画复用 `MediaItem`、`LibraryEntry`、`ContentUnit`、`ReadingProgress` 和来源生命周期语义；漫画页清单、页属性和阅读偏好使用媒介专属结构。页面继续通过 application/repository 边界访问数据，不直接读文件系统或 Drift。

媒体库按媒介导航：小说进入小说详情/阅读器，漫画进入漫画详情/阅读器。归档、恢复、彻底删除和缺失来源提示保持一致，但派生文件清理由媒介仓储负责。

## 6. 验收策略

自动化覆盖自然排序、安全容器、图片验证、事务回滚、迁移、页级进度、缓存键与清理边界；Widget 测试覆盖目录、两种阅读模式、翻页方向、损坏页和错误恢复；Windows 与 Android 使用自建可再分发样例完成人工闭环。性能证据记录机器、构建模式、样本、运行次数和中位数，不以单次观察下结论。

详细任务与依赖见 `docs/m03-task-list.md`。
