# M01-017 TXT 性能基线设计

## 目标

为当前 TXT 导入与阅读链路建立第一份可复现基线。基线用于发现后续回归，不用于宣称“性能达标”，也不在缺乏真实使用反馈时冻结硬阈值。

## 样本

基准工具生成三份 UTF-8 TXT，不提交大文件：

| 样本 | 目标大小 | 用途 |
|---|---:|---|
| small | 100 KiB | 小型文本 |
| regular | 5 MiB | 常规长篇 |
| large | 50 MiB | MVP 0.1 大文件边界 |

内容由英文标题和重复的自建 ASCII 正文组成，章节间隔固定。生成后记录实际字节数和 SHA-256，确保不同机器使用相同输入，不包含商业作品或私人数据。

## 测量链路

每次运行使用独立子进程、临时目录和全新内存数据库：

1. 检查文件元数据并流式计算 SHA-256；
2. 严格 UTF-8 解码；
3. 识别章节；
4. 写入派生文本；
5. 在事务中提交媒体、目录、章节和导入记录；
6. 从数据库加载书籍；
7. 冷读第一章；
8. 读取下一章。

“导入耗时”包含步骤 1 至 5；“打开耗时”包含步骤 6 和 7；“章节切换耗时”包含步骤 8。

## 运行隔离

- 每个样本先预热一次，预热结果不进入统计；
- 每个样本正式运行三次；
- 每次由独立子进程执行，避免数据库、文本缓存和堆内存残留污染下一次；
- 结果以微秒记录，报告以毫秒展示；
- 三次正式结果取中位数。

## 内存

子进程在场景开始前记录 RSS，并在运行期间高频采样：

- `rss_start`：开始前常驻内存；
- `rss_peak`：场景期间观察到的最高常驻内存；
- `rss_delta`：`rss_peak - rss_start`。

RSS 是操作系统视角的进程常驻内存，包含 Dart 运行时、SQLite 和依赖库，不等同于纯 Dart 堆。采样结果是观察值，不保证捕获两个采样点之间的瞬时尖峰。

## 构建模式

正式记录使用 Dart AOT 可执行文件，避免把测试框架和 JIT 编译成本混入结果。报告同时记录 Flutter、Dart、操作系统、CPU、内存和 Git commit。

## 输出

- 机器可读 JSON，便于后续比较；
- Markdown 报告，便于 GitHub 阅读；
- 报告只包含样本标识、哈希、指标和环境信息，不包含临时绝对路径；
- 临时样本、数据库和派生文件在运行结束后清理。

## 限制

- 当前测量的是核心数据链路，不包含 Windows 文件选择器和页面首次绘制；
- RSS 不能替代 DevTools 的 Dart 堆分析；
- 第一份结果只建立基线，不定义通过/失败阈值；
- 本机 MSVC 问题不影响 Dart AOT 基准，但 Windows 应用实机体验仍需另行验收。
