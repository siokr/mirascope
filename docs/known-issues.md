# mirascope 0.3 已知问题

> 适用版本：已发布的 `v0.3.0`；保留仍适用的 0.2 限制。

## 1. 本机 Windows release 构建仍需复验

- 状态：仅本机开发环境限制；
- 历史现象：CMake/MSVC 选择 `HostX86 → x64` 后长时间无编译输出；
- 已知证据：相同仓库在 GitHub `windows-latest` runner 上可生成 release 构建；
- 当前证据：2026-07-30 本机 `flutter run -d windows` 在 26.2 秒内完成 debug 构建并启动真实窗口，已开始核心路径人工验收；
- 剩余影响：本机无法稳定从源码生成 release；GitHub Actions 正式构建和 Windows Sandbox 人工验收均已通过；
- 处理：继续复验 release；若再次挂起，检查 Visual Studio C++ 工作负载与 HostX64 工具链选择，不通过粗暴删除 Flutter 缓存掩盖问题。

## 2. 内容变化后的原位重解析未实现

- 状态：功能限制；
- 当前行为：重新定位时指纹相同则更新路径；指纹不同则拒绝写入并保留当前派生文本、章节和进度；
- 影响：用户修改原 TXT 后不能在原作品中直接采用新内容；
- 安全理由：在新解析结果、章节映射和进度映射能够原子提交前，不执行删除后重导入；
- 临时方式：保留当前作品，或将修改后的文件作为新作品导入。

## 3. Android 正式签名已配置

- 状态：已解决；
- 当前证据：正式标签 `v0.3.0` 的 GitHub Actions #73 已生成正式签名 APK；其签名证书与官方 `v0.2.0` APK 完全一致，Android 16 / API 36 模拟器完成全新安装、漫画导入、双页阅读及重启持久化复验；
- 安全行为：签名材料只通过 GitHub Actions Secrets 注入，不提交私钥或密码；标签构建缺少签名材料时必须失败，不回退到调试签名；
- 维护要求：发布密钥必须在仓库外异地备份；未来 Android 更新继续使用同一密钥签名。

## 4. Windows 实机编码路径已确认

- 状态：已解决；
- 自动化范围：严格 UTF-8、UTF-16、GB18030 字节规则和适配器装配已有测试；
- 人工证据：Windows Sandbox 已完成 UTF-8、UTF-16 和 GB18030 文件导入与阅读；
- 影响：无；异常编码仍按规格拒绝。

## 5. 首次打开会缓存完整规范化文本

- 状态：已测量限制；
- 50 MiB 当前复测：RSS 增量中位数约 `206.74 MiB`；
- 原因：MVP 0.1 解码和阅读阶段允许持有完整文本，阅读仓储按内容引用缓存文本；
- 影响：超大 TXT 的内存占用明显高于原文件大小；
- 计划：先以现有基线观察真实使用，再评估分块读取、索引或其他优化，不提前引入 FFI。

## 6. 当前提供便携压缩包，不提供安装器或降级保证

- 状态：发布形式限制；
- 当前 GitHub Release 提供经干净 Windows Sandbox 验证的便携 ZIP，没有 MSI/MSIX 安装器；
- 数据库支持仓库测试覆盖的 schema v1 到 v2、v2 到 v3 升级；
- 不支持从当前 schema 降级到旧 schema；更新或手工操作应用数据前建议备份整个应用支持目录。

## 7. 已解决的发布收口项

- 项目所有者已选择 MIT License，根目录 `LICENSE` 与 README 声明已加入；
- 直接运行依赖已核对为 MIT 或 BSD-3-Clause 等宽松许可证，Windows 构建会附带项目许可证、第三方概览和从实际 Flutter 构建生成的完整许可证正文；
- `path_provider_android → jni_flutter → jni` 引入的撤回版本 `jni 1.0.1` 已升级为可解析的 `1.0.2`，格式、静态分析和 211 项测试通过。

## 8. Android 本地漫画来源权限限制

- 状态：平台与当前插件限制；
- Android 普通图片目录无法安全保留跨重启的 SAF 文档树权限，因此 0.3 只承诺 ZIP/CBZ 导入闭环；
- 文件选择器会把所选 ZIP 暂存到应用私有缓存；该副本被系统清理后详情页会提示来源不可用；
- 用户选择同指纹的原 ZIP 后可重新定位，已验证页面、进度和阅读偏好均保留；
- 后续若引入原生 SAF 持久权限，必须另行覆盖授权撤销、重启和迁移测试。

## 9. 漫画双页页码显示起始页

- 状态：非阻塞显示限制；
- 双页模式的第一页单独显示，之后按 2—3、4—5 成对显示；
- 底栏当前显示跨页起始页 `1/20`、`2/20`、`4/20`，尚未显示为 `2–3/20`、`4–5/20`；
- 页序、翻页、进度保存和恢复不受影响。
