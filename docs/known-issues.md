# mirascope MVP 0.1 已知问题

> 适用版本：`0.1.0+1` 候选开发版

## 1. 本机 Windows release 构建仍需复验

- 状态：debug 构建与启动已恢复，release 构建尚未重新确认；
- 历史现象：CMake/MSVC 选择 `HostX86 → x64` 后长时间无编译输出；
- 已知证据：相同仓库在 GitHub `windows-latest` runner 上可生成 release 构建；
- 当前证据：2026-07-30 本机 `flutter run -d windows` 在 26.2 秒内完成 debug 构建并启动真实窗口，已开始核心路径人工验收；
- 剩余影响：release 构建、安装验证和被缺陷阻断的人工场景仍待补验；
- 处理：继续复验 release；若再次挂起，检查 Visual Studio C++ 工作负载与 HostX64 工具链选择，不通过粗暴删除 Flutter 缓存掩盖问题。

## 2. 内容变化后的原位重解析未实现

- 状态：功能限制；
- 当前行为：重新定位时指纹相同则更新路径；指纹不同则拒绝写入并保留当前派生文本、章节和进度；
- 影响：用户修改原 TXT 后不能在原作品中直接采用新内容；
- 安全理由：在新解析结果、章节映射和进度映射能够原子提交前，不执行删除后重导入；
- 临时方式：保留当前作品，或将修改后的文件作为新作品导入。

## 3. Windows 实机编码路径尚未人工确认

- 状态：待验收；
- 自动化范围：严格 UTF-8、UTF-16、GB18030 字节规则和适配器装配已有测试；
- 未确认范围：Windows 原生文件选择器和 GB18030 平台转换的真实交互；
- 影响：不能把自动化通过描述为所有本地编码文件已经实机验证。

## 4. 首次打开会缓存完整规范化文本

- 状态：已测量限制；
- 50 MiB 基线：RSS 增量中位数约 `209.52 MiB`；
- 原因：MVP 0.1 解码和阅读阶段允许持有完整文本，阅读仓储按内容引用缓存文本；
- 影响：超大 TXT 的内存占用明显高于原文件大小；
- 计划：先以现有基线观察真实使用，再评估分块读取、索引或其他优化，不提前引入 FFI。

## 5. 尚无正式安装包和升级/降级保证

- 状态：候选阶段限制；
- 当前只有源码和 CI 构建证据，没有已安装验证的公开附件；
- 数据库支持仓库测试覆盖的 schema v1 到 v2 升级；
- 尚未发布过生产版本，因此没有对生产数据降级到旧 schema 的保证；
- 尝试候选版前应备份应用数据，正式 Release 前需要完成干净环境安装和迁移验证。

## 6. 尚未选择开源许可证

- 状态：项目所有者待决策；
- 影响：代码公开可见不等于授予复制、修改或再分发权；
- 处理：公开推广、接受外部贡献或发布正式版本前选择并提交许可证，同时核对第三方许可证。

## 7. 依赖树包含已撤回的传递依赖

- 状态：正式发布前待处理；
- 现象：`flutter pub get --offline` 提示 `jni 1.0.1` 已被撤回；
- 来源：当前依赖树由 Android 平台的 `path_provider_android → jni_flutter → jni` 引入，不是项目直接声明；
- 当前影响：MVP 0.1 只承诺 Windows，现有 Windows 自动化和 release 构建通过，但锁文件仍包含该包；
- 处理：MVP 0.2 启动 Android 支持前必须升级到不依赖撤回版本的兼容组合；正式公开 Release 前也应完成依赖与第三方许可证审计。

## 8. 明确不属于 MVP 0.1

以下不是缺陷，而是尚未进入当前范围：

- EPUB 和 Android；
- 书签；
- 漫画与图片缓存；
- 账号、跨设备同步和服务端；
- 在线内容源、下载和番剧；
- Rust 性能模块。
