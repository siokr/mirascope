# mirascope MVP 0.1 演示指南

## 1. 状态

本指南定义 `0.1.0+1` 候选版应执行的核心演示路径。步骤来自当前代码，但维护者机器尚未完成 Windows 实机走查；执行后必须在候选记录中补充日期、提交和结果。

## 2. 演示数据

只使用自己编写或许可明确的 TXT。建议准备：

1. UTF-8 多章节小说：至少 3 章；
2. 同一文件的复制品：用于重复导入；
3. 内容相同但路径不同的文件：用于重新定位；
4. 内容不同的 TXT：用于验证不同指纹保护；
5. 可选的 UTF-16 或 GB18030 小样本。

示例正文可以使用：

```text
第一章 开始
这是自建的演示文字。

第二章 继续
这里用于验证章节切换和进度。

第三章 结束
这里用于验证目录和恢复。
```

不得使用未获授权的商业小说，也不要让真实私人路径出现在截图或日志中。

## 3. 五到八分钟核心演示

### 3.1 启动与空状态

1. 启动 Windows 应用；
2. 确认进入“媒体库”；
3. 确认空状态、已归档入口、设置入口和“导入 TXT”按钮可理解。

### 3.2 导入

1. 点击“导入 TXT”；
2. 选择 UTF-8 演示文件；
3. 输入书名并继续；
4. 确认导入后打开小说详情；
5. 确认标题、章节数和目录顺序正确。

如自动编码无法确定，选择明确编码后重试；取消选择或取消书名不应显示错误。

### 3.3 阅读

1. 点击“开始阅读”；
2. 滚动到本章中部；
3. 使用按钮或左右方向键切换章节；
4. 打开目录并跳转章节；
5. 打开阅读设置，调整字号、行距和护眼主题；
6. 确认首章不能“上一章”、末章不能“下一章”。

### 3.4 进度恢复

1. 在非首章滚动到明显位置；
2. 正常关闭应用；
3. 再次启动并打开同一本书；
4. 确认恢复到相同章节和近似字符位置；
5. 再执行一次由任务管理器终止的异常退出恢复。

正常关闭和异常终止需要分别记录，不能用 Widget 测试代替。

### 3.5 文件变化

1. 关闭应用并移动原 TXT；
2. 再次打开作品，确认媒体、目录和进度仍存在；
3. 点击“重新定位源文件”并选择内容相同的文件；
4. 确认恢复阅读且进度保留；
5. 再选择内容不同的文件；
6. 确认应用拒绝静默替换，并说明当前可读版本和进度已保留。

### 3.6 媒体库管理

1. 回到媒体库；
2. 归档作品，确认提示不会删除原文件；
3. 使用“撤销”或“已归档”页面恢复；
4. 再次导入相同内容，确认打开已有作品而不是创建重复条目。

## 4. 补充错误路径

- 空文件；
- 不存在或无权限文件；
- 无法可靠识别的编码；
- 无可读正文；
- 数据加载失败后的“重试”；
- 超长书名和窗口缩放；
- 浅色、深色主题与键盘操作。

错误反馈不得显示完整路径、正文、原始异常或堆栈。

## 5. 截图建议

只截取实际运行的 `0.1.0+1` 候选版：

1. 有内容的媒体库；
2. 小说详情与目录；
3. 阅读器和设置面板；
4. 来源丢失与重新定位提示。

截图前检查标题、路径和系统通知是否包含私人信息。记录截图对应的 Git commit，不使用设计稿冒充运行结果。

- Flutter/Dart 版本；

- 异常终止恢复结果；
- 原生文件选择与 GB18030 结果；
- 截图或视频路径；
- 发现的问题和严重级别。
