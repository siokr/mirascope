# 0002 使用 go_router 并手写 MVP 路由

- 状态：accepted
- 日期：2026-07-27
- 决策者：项目维护者

## 背景

MVP 0.1 需要媒体库、设置、小说详情和阅读器之间的声明式导航，并为错误页和后续深链保留清晰扩展点。

## 评估标准

- 与 Flutter Router API 的一致性；
- 路径参数和错误处理；
- Widget 测试便利性；
- 首版配置复杂度；
- 后续 Android 深链和账号重定向能力。

## 备选方案

### go_router

提供声明式路径、参数、错误处理和重定向，属于 Flutter 官方发布生态。可手写路由，也可后续增加类型安全生成。

### Navigator API

依赖最少，但需要自行组织声明式路由、路径解析和错误页面。

### auto_route 或其他生成式路由

类型安全和样板较少，但会增加注解、生成器和第三方抽象；MVP 0.1 只有少量固定页面。

## 决策

采用 go_router，MVP 0.1 手写路由表，不引入路由生成器。

首批路径为：

```text
/library
/settings
/novel/:mediaItemId
/novel/:mediaItemId/read
```

路由器集中在 `src/app/router`，初始位置为 `/library`。无效参数进入可恢复错误页。

## 后果

收益：

- 路由结构显式且易于测试；
- 保留深链和后续重定向能力；
- 首期避免第二套路由代码生成。

代价：

- 路径和参数类型需要手写约束；
- 路由规模扩大后可能产生重复字符串。

## 复核条件

当路由数量、嵌套导航或参数模型明显增长，并出现真实的路径重构错误时，再评估 `go_router_builder` 等类型安全方案。
