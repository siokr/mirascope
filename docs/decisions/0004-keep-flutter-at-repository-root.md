# 0004 保留根目录 Flutter 工程

- 状态：accepted
- 日期：2026-07-27
- 决策者：项目维护者

## 背景

仓库当前是标准 Flutter 多端工程。Go 服务要到 Version 0.4 才进入，Rust 没有固定排期。现在迁移到 `client/flutter_app/` 会修改全部平台路径、工具命令和 CI，却不增加 MVP 0.1 用户价值。

## 评估标准

- 当前开发和构建复杂度；
- 未来服务端扩展；
- GitHub 可理解性；
- 路径迁移成本；
- 是否存在多个独立可发布单元。

## 备选方案

### 保留根目录 Flutter 工程

与当前工具和平台目录一致，变更最小；未来新增服务端时需要再次评估仓库结构。

### 立即迁移到 `client/flutter_app/`

从一开始形成多语言 monorepo 外观，但当前会产生大量无业务价值的路径调整。

### 分离多个仓库

客户端和服务端边界最清楚，但早期增加版本协调和公开展示成本。

## 决策

MVP 0.1 和 MVP 0.2 保留根目录 Flutter 工程。代码仅在 `lib/src` 内按应用、基础设施和 feature 分层。

不提前创建 `server`、Rust 或未来 feature 空目录。

## 后果

收益：

- 保持 Flutter 默认工具兼容；
- 应用骨架任务集中在真实代码结构；
- GitHub 访问者可直接使用标准 Flutter 命令。

代价：

- Version 0.4 可能需要一次顶层目录决策；
- 未来 monorepo 工具引入时需要更新脚本和文档。

## 复核条件

出现 Go 服务、第二客户端、独立包发布需求，或根目录结构开始妨碍构建和 CI 时，通过新 ADR 重新评估。
