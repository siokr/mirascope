# 架构决策记录

## 1. 用途

ADR 用于记录会长期影响实现、依赖或维护成本的技术选择。它回答“为什么这样选”，不替代专题规格和任务清单。

## 2. 文件命名

```text
NNNN-short-title.md
```

编号从 `0001` 递增。标题使用英文小写和连字符，正文使用中文。

## 3. 状态

- `proposed`：正在评审；
- `accepted`：当前有效；
- `superseded`：被新 ADR 替代；
- `rejected`：评估后未采用。

被替代的 ADR 不删除，并链接到替代它的新记录。

## 4. 模板

```markdown
# NNNN 决策标题

- 状态：proposed
- 日期：YYYY-MM-DD
- 决策者：项目维护者

## 背景

描述需要解决的问题、约束和触发时机。

## 评估标准

列出可测试性、跨平台、迁移、性能和维护成本等标准。

## 备选方案

逐项说明方案及优缺点。

## 决策

明确采用的方案和适用边界。

## 后果

记录收益、代价、风险和后续复核条件。
```

模板中的示例日期在创建 ADR 时必须替换为实际日期。

## 5. 首批决策

Phase 0 开始实现前应分别记录：

1. Flutter 状态管理方案；
2. 路由方案；
3. 本地数据库方案；
4. 当前保留根目录 Flutter 工程的仓库结构方案。

每项必须比较实际备选方案，不能只写“社区流行”。
