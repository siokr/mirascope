# 0003 使用 Drift 管理本地关系数据

- 状态：accepted
- 日期：2026-07-27
- 决策者：项目维护者

## 背景

项目需要媒体、媒体库、章节、进度、导入记录和后续书签之间的关系、事务、索引与迁移。Windows 是 MVP 0.1 主平台，Android 在 MVP 0.2 加入。

## 评估标准

- Windows 与 Android 支持；
- 类型安全查询；
- 事务和约束；
- schema 迁移与测试；
- 响应式媒体库查询；
- 数据层可替换与领域隔离；
- 单人维护成本。

## 备选方案

### Drift

基于 SQLite，提供类型安全生成、事务、迁移工具、复杂查询和响应式流，支持 Windows 与 Android。

### sqflite / sqlite3 直接封装

控制直接、依赖更少，但表映射、查询类型、迁移验证和响应式更新需要自行建设。

### 文档或对象数据库

初期模型简单，但项目的唯一约束、章节顺序、迁移和后续同步镜像更适合显式关系模型。

## 决策

采用 Drift + drift_flutter，并使用 drift_dev 与 build_runner。

- schema version 从 1 开始；
- 表、索引、约束和迁移由数据层定义；
- 使用内存数据库测试事务和迁移；
- Drift 生成的数据类不进入 Widget；
- Repository 映射到 `docs/data-model.md` 定义的领域模型；
- 数据库打开失败或迁移失败时不自动删库。

## 后果

收益：

- 查询和表结构具备编译期检查；
- 支持事务、响应式媒体库和迁移验证；
- Windows/Android 使用同一关系模型。

代价：

- 需要生成文件和迁移纪律；
- Drift 类型与领域类型之间存在映射代码；
- SQLite 约束和平台文件位置需要集成测试。

## 复核条件

只有 Drift 在目标平台出现无法规避的稳定性、性能或迁移问题时才重新选型。普通映射样板不是更换数据库的充分理由。
